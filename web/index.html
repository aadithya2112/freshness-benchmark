PROTOCOL 2 / MIXED MUTATIONS

Methodology

Visibility is observed through the API. It is an upper bound that includes client queues, transport, and query execution—not a timestamp inside the index.

01

Submit

Readers begin at submission, independently of the writer’s acknowledgement.

02

Observe

Check both direct-ID state and the expected version through vector search.

03

Confirm

Require at least three correct observations spanning 50ms on each channel.

WHAT COUNTS AS FRESH

One rule for each kind of change.

Insert
The new document is present in a direct read and appears with version 1 in unfiltered top-10 self-vector search.
Replacement
The same ID returns version 1 after replacing both its content and vector. Before the write, the target must be absent from search with its new vector. Merely finding the old ID does not count.
Deletion
A previously retrievable document becomes absent in both direct-ID reads and repeated searches with its old vector. A negative ANN result alone never establishes deletion.

Confirmation describes the observed window. It does not prove permanent absence or monotonic visibility. Regressions reset the confirmation window and are counted.

RETRIEVAL QUALITY

Speed needs a quality check.

Background traffic uses 100 real dataset questions. Queries filter to an immutable cohort in the same collection, while mutations target disjoint IDs. This gives a fixed, exact reference during concurrent writes.

ANN recall@10 measures agreement with exhaustive cosine search. Equal-score neighbors at the tenth boundary receive credit within a 10⁻⁶ tolerance. The eligibility target is 95% recall before and during the workload.

nDCG@10 uses human relevance judgments and is reported separately. It reflects the fixed embedding model and transformed corpus as well as retrieval. These subset scores are not full BEIR leaderboard scores.

This quality workload is filtered. Mutation probes search the whole collection. The two workloads answer different questions and remain labelled throughout the results.

VALIDITY GATES

Keep failures in view.

  • p95 arrival delay ≤ the shortest requested interarrival interval.
  • p95 probe dispatch delay ≤ 10ms. Positive responses are sampled every 25ms; negative responses use a minimum 10ms gap.
  • p95 background-query dispatch delay ≤ its requested interarrival interval.
  • ANN recall ≥95% before and during mutations.
  • All mutation preconditions pass; no client-capacity drops or results from outside the requested static cohort.
  • HNSW configuration, index readiness, and PostgreSQL query plan are verified.

A cell is eligible only when all planned trials complete and pass every gate. Failed cells remain visible. Database errors and timeouts remain in the reliability denominator even when the harness gates pass.

CALIBRATION

Test the clock against known delays.

Controlled in-memory backends inject 0, 25, and 100ms of visibility delay. A separate 100ms acknowledgement delay checks that readers can observe a change before the writer receives its response. These controls measure harness behavior; they do not calibrate network or server overhead.

EXPERIMENT DESIGN

Repeated runs, declared conditions.

Each trial gets a new collection and a deterministic, disjoint mutation plan. Inserts, replacements, and deletes rotate in equal proportions. These are simulated mutations of static corpora, not replayed historical events.

After loading and index-readiness checks, every mutation target is checked. A two-second query warmup precedes a idle baseline covering all 100 queries (ten seconds at the reference rate). The measured mixed workload lasts 30 seconds. The burst profile uses four times the nominal rate during the first second of each ten-second period.

Five randomized trials per cell run on one local Apple M4 host through Docker Desktop. Each backend receives two virtual CPUs and 3 GiB. Collections are removed after each trial. Host activity, shared physical resources, caching, and backend-specific acknowledgement semantics remain limitations. Cgroup CPU, throttling, and memory counters are included in each trial record.

We report the median of trial p95s and a seeded percentile bootstrap interval using 5,000 trial-level resamples. Five trials offer limited uncertainty resolution. The intervals do not establish statistical significance or a universal winner.

Qdrant uses wait=true; Weaviate uses synchronous indexing and REST writes with GraphQL queries; PostgreSQL uses autocommit, READ COMMITTED and independent connections. HNSW parameters and actual versions are retained in each run. Equal numerical parameters do not imply equivalent algorithms or durability.

RELATED WORK

Part of a larger measurement effort.

ANN-Benchmarks ↗ establishes recall/performance comparisons. VectorDBBench ↗ includes database workloads and ingestion/readiness measurements. FreshDiskANN ↗ studies concurrent updates, deletion, search, and recall. BEIR ↗ supplies real retrieval tasks and judgments.

This project brings version-aware observations, independent readers, quality gates, and inspectable evidence into one comparison workflow. It makes no claim to be the first freshness benchmark.

EMBEDDINGS

One model, outside the clock.

all-MiniLM-L6-v2 ↗ produces normalized 384-dimensional vectors, cached as float32 arrays. Model revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41 is pinned. Input is limited to 200 words, then the model’s 256-token limit. Model license: Apache-2.0.

Regenerated floating-point vectors can vary across devices. The manifest identifies the exact cache used. Data licenses remain separate from the benchmark’s MIT code license.

Dataset attributions and retained licenses are also included in the downloadable source under docs/DATA-NOTICE.md.

The earlier Python documentation pilot is retained in the source repository as historical evidence. Its small insertion-only measurements are not mixed with protocol 2 results.

RUN THE MATRIX

Same workload. Your hardware.

Python 3.12, uv and Docker are the reference environment. Data preparation downloads the BEIR archives and model weights. The complete matrix is substantial; start with the smoke suite. 

uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e '.[publication]'
docker compose -p freshness-v2 -f docker-compose.v2.yml up -d
.venv/bin/python scripts/prepare_v2_data.py scifact --device cpu
.venv/bin/python scripts/prepare_v2_data.py nq --device cpu
.venv/bin/python -m unittest discover -s tests
.venv/bin/python scripts/run_streaming.py \
  --out artifacts/my-v2 --trials 5 --duration 30
.venv/bin/python scripts/build_website.py artifacts/my-v2
.venv/bin/python scripts/verify_v2.py artifacts/my-v2

CPU regeneration produces its own cache hash. Report it; do not claim byte-identical reproduction unless the cache hashes match. The reference used Apple MPS for embedding preparation only.
